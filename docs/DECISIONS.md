# AquaShift — Architecture & Technical Decision Record (ADR)

This document tracks all key technical decisions, trade-offs, and design rationale across the project.

| ID | Date | Status | Context | Decision | Consequence / Rationale |
|---|---|---|---|---|---|
| **D-001** | 2026-10-30 | Accepted | Root directory layout | Deploy project modules directly in workspace root (`/Users/ayushrana/Downloads/AquaShift/`) rather than a nested `aquashift/` directory. | Simplifies dev tooling, scripts, and prevents path confusion across cross-platform runners. |
| **D-002** | 2026-10-30 | Accepted | Python 3.11 runtime management | Use standalone CPython 3.11.18 managed via `uv` to create local `.venv`. | Satisfies strict Python 3.11 requirement on macOS host with pinned dependencies. |
| **D-003** | 2026-10-30 | Accepted | API architectural boundaries | Organize backend into `app/api/`, `app/core/`, `app/models/`, `app/ml/`, `app/optimizer/`, `app/llm/`. | Strict separation of concerns: routes delegate all computation to pure domain modules; no business logic in route handlers. |
| **D-004** | 2026-10-30 | Accepted | Guaranteed solver feasibility | Enforce hard bounds on land and rotation share only; model water, food, and income targets with non-negative slack variables ($s \ge 0$). | Guarantees that extreme scenarios return closest-feasible allocations with diagnosed bottlenecks instead of bare `INFEASIBLE`. |
| **D-005** | 2026-10-30 | Accepted | Offline-first explanation pipeline | Make Anthropic Claude integration completely optional; provide full deterministic templates for farmer and planner personas. | Ensures hackathon presentation works 100% reliably offline without API keys or network latency. |
| **D-006** | 2026-10-30 | Accepted | Frontend tech stack | React 18 + Vite + TypeScript + Tailwind CSS + Recharts. | High-performance SPA with type safety, responsive earth-to-aqua UI design, and fast chart rendering. |
| **D-007** | 2026-10-30 | Accepted | Frontend dependency pinning | Strip caret (^) and tilde (~) from `frontend/package.json` and pin exact installed versions matching `package-lock.json`. | Guarantees deterministic, reproducible builds across development and judging environments with `npm ci`. |
| **D-008** | 2026-10-30 | Accepted | Synthetic data generation methodology | Implement FAO-56 crop-water response ($Y_a / Y_m = 1 - K_y(1 - ET_a/ET_m)$) with bounded stochastic perturbation ($\pm 5\%$) and a fixed random seed (42). | Ensures strictly monotonic yield response under water deficits while providing realistic variance for ML regressor training. |
| **D-009** | 2026-10-30 | Accepted | Punjab/Haryana indicative crop calibration | Calibrate Paddy (12,500 m³/ha, $K_y=1.20$), Wheat (4,500 m³/ha, $K_y=1.00$), Maize (5,500 m³/ha, $K_y=1.15$), Pulses (3,000 m³/ha, $K_y=0.85$), and Millets (2,200 m³/ha, $K_y=0.65$) against public reports (CACP MSP 23-24, ICAR, CGWB). | Reflects the real economic and hydrological trade-offs of the northwest Indo-Gangetic plain. |
| **D-010** | 2026-10-30 | Accepted | Monotonic ML estimators with non-redundant features | Train separate `HistGradientBoostingRegressor` estimators for yield and irrigation demand using `scikit-learn`. Enforce monotonicity via `monotonic_cst=[1, 0, 1, 1, 1]` on yield and `[1, -1]` on water demand. Exclude `water_availability_ratio` from water demand estimator. | Mathematically guarantees yield non-decrease under water improvements, satisfies physical limits, and avoids feature multicollinearity. |
| **D-011** | 2026-10-30 | Accepted | Deterministic OR-Tools LP optimizer with recovery slacks and diagnosis | Implement linear programming using Google OR-Tools `pywraplp` with GLOP solver. Decision variables $x_i \ge 0$ define continuous crop hectares. Hard constraints strictly enforce land conservation ($\sum x_i = L$) and crop share bounds ($\underline{s}_i L \le x_i \le \overline{s}_i L$). Soft constraints model water budget, food target, and net income with nonnegative slacks ($s_w, s_f, s_i \ge 0$) normalized by positive scenario scales. Implement two modes: (1) weighted normalized slacks with small $10^{-5}$ water tie-breaker, and (2) sequential lexicographic solve (Water $\to$ Food $\to$ Income) with $10^{-4}$ objective preservation. GLOP dual values are labeled as local model sensitivity. Diagnosis ranks resource bottlenecks into Critical, High, and Moderate tiers. | Guarantees deterministic, millisecond-scale optimization; prevents bare `INFEASIBLE` solver errors under stress scenarios; recovers closest-feasible plans and provides transparent bottleneck explanations. |
| **D-012** | 2026-10-30 | Accepted | FastAPI REST API Architecture, Pipeline Integration & Zero-Traceback Error Handling | Expose all core pipeline functions (configuration, baseline, ML predictions, OR-Tools optimization, extreme scenario stress test, and parametric water sweeps) via modular FastAPI routers under `backend/app/api/`. Enforce strict Pydantic v2 request/response schemas. Integrate an in-memory thread-safe LRU cache for identical scenario requests. Implement global exception handlers for `OptimizationValidationException`, `RequestValidationError`, and generic `Exception` to ensure structured JSON responses and zero internal traceback leakage to clients. Ensure complete offline operation without external network dependencies. | Clean separation of HTTP routing from mathematical optimization; fast sub-millisecond cached responses; standard OpenAPI documentation at `/docs`; robust client error feedback. |
